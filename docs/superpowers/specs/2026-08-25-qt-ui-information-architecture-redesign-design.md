# Qt 桌面界面信息架构与视觉重构设计

## 1. 背景

当前 Qt 5.14.2 Widgets 应用已具备工件建库、单张检测、批量检测、人工确认异步入库、几何干扰规则标定与发布等完整能力，但功能逐步增加后，主窗口和几何规则管理器已经出现明显的信息架构问题：

- 后端状态、工件管理、建库、检测、批量复核和规则管理处于同一视觉层级；
- 高频检测操作与低频工程配置互相挤占空间；
- 主要按钮、普通按钮和危险操作缺少清晰的视觉权重；
- 复杂状态主要依赖红色文字、灰色禁用按钮或原始诊断内容解释；
- 几何规则的编辑、拟合、模板复核、迁移、验证、发布和回退同时呈现，用户难以判断下一步；
- 基础控件位于 `mainwindow.ui`，部分关键控件又由 C++ 动态插入，界面结构与业务状态相互缠绕。

本设计不增加识别算法功能，而是重新组织现有能力，使应用默认服务于生产现场的单张连续检测，同时把工件维护和几何规则配置放入清晰的独立页面。

## 2. 已确认的产品决策

1. 默认工作模式为“日常检测优先”。
2. 同一程序不增加登录或账号权限；检测与管理通过页面分区避免误操作。
3. 单张连续检测为主要输入方式，批量检测为检测页内的次级模式。
4. 以 1920×1080 为主要设计基准。
5. 主检测页采用“方案 A：双栏检测台”。
6. `检测`、`工件库`、`几何规则` 均在同一主窗口内切换完整页面。
7. 识别依据默认展示摘要，详细得分和诊断按需展开。
8. 几何规则采用简化流程：自动拟合与验证，无阻断时一键发布；异常和高级配置按需展开。

## 3. 目标

1. 启动后直接进入单张检测，当前工件、待测图片、最终判定和确认动作始终清晰可见。
2. 将检测、工件维护和规则配置拆为三个同窗一级页面，避免任务上下文混杂。
3. 让批量结果、当前图片、识别证据和确认对象始终保持一一对应。
4. 让工件库真实呈现任意、不等数量的正反模板，并清楚反馈建库与异步入库状态。
5. 让一条几何规则在正反面始终可见，分别标定，并通过单一主操作完成保存、验证和发布。
6. 建立可复用的视觉、状态和错误反馈规范，替代散落在 C++ 与 UI 文件中的临时样式。
7. 在不改变后端协议语义、模型和融合逻辑的前提下渐进迁移，降低行为回归风险。

## 4. 非目标

- 不重新训练或替换模型。
- 不修改 PP-ShiTu、ALIKED、LightGlue、融合阈值和几何遮罩算法语义。
- 不新增账号、权限或登录系统。
- 不新增相机实时采集协议。
- 不把后端改造成多请求并行服务。
- 不在本次变更中继续优化模型推理耗时。
- 不迁移到 QML、Web 技术或新的 UI 框架。

## 5. 总体信息架构

```text
MainWindow
├─ AppHeader
│  ├─ 一级导航：检测 / 工件库 / 几何规则
│  ├─ 当前工件
│  └─ 后端状态与诊断入口
├─ QStackedWidget
│  ├─ InspectionPage
│  │  ├─ 单张检测
│  │  └─ 批量检测
│  ├─ WorkpieceLibraryPage
│  └─ GeometryRulesPage
└─ GlobalTaskStatus
```

应用启动后默认进入 `InspectionPage` 的单张模式。三个一级页面使用同一主窗口切换，不再通过多个大型管理对话框分散上下文。

顶部应用栏始终显示当前页面、当前工件和后端状态。点击后端状态打开详情面板，显示连接、模型加载、当前任务、最近错误和允许执行的恢复操作。全局错误不再只以孤立红字显示。

顶部“当前工件”是检测目标。工件库页面中浏览或编辑其他工件只改变详情选择，不得静默切换检测目标；只有用户在顶部选择器中确认，或在工件详情中执行明确的“设为当前工件”，才更新检测目标。

页面切换只改变显示，不重新加载模型，也不自动清空检测结果、批量任务、工件编辑内容或规则草稿。离开存在未保存内容的页面时必须提示。正在运行的建库、验证或异步入库任务通过 `GlobalTaskStatus` 跨页面持续可见。

## 6. 检测页面

### 6.1 单张检测布局

检测页使用约 65% : 35% 的可调双栏：

- 左侧为当前图片大图、文件信息和缩放/复位工具；
- 右侧为最终判定、可信状态、复检状态、证据摘要和确认操作；
- 底部为最近检测缩略记录；
- 选择文件、拖放图片和开始检测均位于图片区域附近。

右侧只突出一个当前结果。预测为正面时，操作为“确认正面 / 修正为反面 / 不入库”；预测为反面时正反操作自动互换。确认后异步入库，不阻塞下一张检测，并显示“等待写入 / 正在更新缓存 / 已参与预测 / 写入失败”。

证据摘要默认展示全局特征、局部匹配、几何规则和复检原因等三至四条关键结论。候选模板、原始得分、匹配细节和分阶段耗时放入可展开详情，不在主流程中显示原始 JSON。

现有全局/局部得分与间隔不是校准概率，因此不得把它们直接转换成“96.8%”一类百分比置信度。主结果区显示“可信 / 需要复核”等现有决策状态；只有后端未来明确返回经过校准的概率字段时，才允许展示百分比。

底部最近记录保留图片缩略图、结果、时间、复检标记和入库状态。点击记录恢复对应图片和证据，但不自动重新提交预测。

### 6.2 检测状态

- `idle`：中性空状态，提示选择或拖入图片；
- `running`：显示当前阶段和进行中状态；
- `completed`：突出最终判定与下一步操作；
- `needs_review`：使用图标、琥珀色和明确文字提示人工复核；
- `failed`：保留当前图片，显示具体原因与重试入口；
- `backend_unavailable`：保留现场结果，禁止新提交，并提供诊断/重启入口。

颜色不能作为唯一状态媒介。后端断开、超时或重启不得清空已展示图片和结果。

### 6.3 批量模式

批量检测在检测页内切换独立模式，不增加第四个一级页面。它复用左侧图片和右侧结果卡，底部最近记录区域扩展为可调整高度的结果表。

结果表至少提供：

- `全部`、`待复核`、`未处理`、`失败`筛选；
- 总体进度、成功数、待复核数和失败数；
- 文件、预测结果、复检状态、耗时和处理状态；
- 停止继续提交尚未执行图片的入口；已经发送给后端的当前请求等待正常返回，不增加后端取消协议。

点击任意结果行必须同时更新左侧图片、右侧判定、证据和确认对象。确认当前行后自动定位到下一条待处理记录，优先处理待复核项。批量记录使用稳定身份关联，不以表格行号作为业务身份。

## 7. 工件库页面

工件库使用“左侧列表 + 右侧详情”布局。

左侧支持搜索并显示工件名称、正反模板数量、规则数量、可检测状态和最近更新时间。右侧显示工件概览、模板缩略图、最近异步入库记录和建库记录。

正反模板数量分别显示真实值，不要求相同，不显示固定分母。模板详情至少包括方向、来源、入库时间和可读状态。

新建或更新工件使用独立编辑区：

- 正面、反面分别选择任意正整数张图片；
- 显示实际选择数量与全部缩略图，不截断用户选择；
- 空列表、不可读取图片、正反重复图片就地标记并阻止提交；
- 模板较少或超过 30 张只显示质量/性能提醒，仍允许继续；
- 所有通过校验的已选图片都写入模板缓存并参与预测，不允许静默忽略；
- 建库时显示阶段、完成数/总数、百分比和已耗时；
- 建库完成后显示实际写入的正反模板数和总耗时。

经检测确认的图片进入“最近入库”，展示等待提取特征、更新缓存、已参与预测或失败原因。异步生成新缓存时，旧缓存继续提供预测；新缓存完整生成后原子切换。

“删除工件”为危险操作，必须二次确认工件名称。旧版 5+5 工件库继续按现有兼容路径恢复，不要求重新训练或手工迁移。

## 8. 几何规则页面

几何规则从大型对话框调整为完整页面，采用“规则列表 + 标定画布 + 状态与操作”三栏可调布局。

### 8.1 单一逻辑规则与双向标定

每个规则在逻辑上只有一条，例如“中心反光”。规则共享名称、忽略内部/外部方式和带符号边界偏移；正面与反面分别保存标定边界、拟合结果和状态。

切换正反方向时同一规则始终可见，并明确显示：

- 已标定；
- 待标定；
- 拟合失败；
- 已发布版本中的只读状态。

另一方向未完成时，界面引导用户切换到对应模板标定，不创建同名隐藏规则。

### 8.2 画布显示

继续支持现有圆、椭圆、矩形等形状，所有形状均可保存，没有默认主工具。用户绘制内容只是拟合引导。

完成拟合并保存后，默认隐藏手绘虚线，显示程序拟合出的实线边界。画布提供常驻图例和显示开关：

- 手绘引导；
- 拟合边界；
- 应用边界偏移后的最终边界或忽略范围。

边界偏移使用统一的带符号百分比：负数向内缩小，正数向外扩大；忽略内部与忽略外部均使用相同符号语义，并在画布实时预览。

缩放、平移和复位只改变显示变换，不改变原图像素坐标及最终遮罩。

### 8.3 简化验证与发布

主流程为：

1. 绘制粗略引导边界；
2. 自动拟合当前模板并显示结果；
3. 点击“保存、验证并发布”；
4. 系统自动保存草稿并验证全部模板；
5. 无阻断项时直接发布；有阻断项时停止发布并定位问题。

页面正常状态只突出一个主按钮。验证摘要显示通过数、低置信度数、未配置数和拟合失败数。每个问题都必须包含原因和“定位模板”操作，不能只藏在原始诊断文本中。

候选、残差、迁移冲突、覆盖原因和原始诊断默认收纳在“高级设置”。只有检测到旧规则迁移冲突时才显示迁移区域。发布成功后显示活动版本，并提供历史版本与回退入口。

禁用主按钮时，按钮附近必须显示禁用原因。

## 9. 视觉系统

采用克制的浅色工业风格：

| 用途 | 色值 |
| --- | --- |
| 页面背景 | `#F4F6F8` |
| 内容面板 | `#FFFFFF` |
| 主文字 | `#17212B` |
| 次级文字 | `#5F6B76` |
| 主操作 | `#2563EB` |
| 成功 | `#15803D` |
| 警告/待复核 | `#B7791F` |
| 错误/危险 | `#C9362B` |
| 边框 | `#D9E0E7` |

界面以 8 px 为基础间距单位，页面外边距 24 px，面板内边距 16–24 px，圆角限制在 4–6 px。不使用渐变、玻璃效果、大面积阴影或过度圆角。

字体以微软雅黑为主：普通内容 13–14 px，控件 14 px，分区标题 16–18 px，页面标题 22–24 px，最终正反判定 36–48 px。诊断数值可使用等宽字体。

每页最多突出一个主操作。普通操作使用次级或描边按钮；删除、覆盖等危险操作使用红色并二次确认。图标统一使用一套 Qt 资源内的 SVG 线性图标，不使用字符图标或表情符号。

长文件名和路径自动省略，悬停显示完整值。表格行具有明确的悬停、选择与处理状态。禁用控件必须提供原因说明。

## 10. 通用状态与错误反馈

- 耗时超过约 300 ms 的操作显示执行状态；
- 成功提示可以短暂显示，但关键结果必须保留在页面；
- 字段错误在字段附近显示，全局错误显示在页面级状态区；
- 错误信息包括发生原因和重试、定位、刷新或重启等恢复操作；
- 后端连接、模型加载、任务繁忙和不可用状态使用统一组件；
- 页面切换与连接恢复不得静默清空用户输入或结果；
- 未保存草稿、危险删除、覆盖发布和关闭进行中任务均使用明确确认对话框。

## 11. Qt 组件边界与状态流

建议拆分：

- `MainWindow`：应用外壳、页面导航、当前工件、后端状态和全局任务；
- `InspectionPage`：单张/批量模式、图片、结果、证据和人工确认；
- `WorkpieceLibraryPage`：工件列表、模板编辑、建库与异步入库记录；
- `GeometryRulesPage`：规则选择、画布、双向标定、验证与发布；
- 共享组件：图片查看器、结果卡、证据摘要、状态消息、任务进度、缩略图列表、确认框和后端详情。

状态流保持单向：

```text
页面意图 → 统一任务协调 → 现有 BackendClient
         ← 页面/全局状态更新 ← 后端响应、进度或错误
```

`BackendClient` 的请求序列化、握手、超时和后端进程所有权语义保持不变。视觉上不得表现为后端能够并行执行多个业务请求。

主窗口统一持有当前工件、后端状态和跨页面任务；页面分别持有检测结果、批量选择、工件编辑内容与几何草稿。导航不应成为隐式清空状态的触发器。

## 12. 渐进迁移策略

1. 建立统一主题、图标和共享状态组件，不改变业务行为。
2. 引入 `QStackedWidget` 页面导航，先复用现有信号与对象名称。
3. 拆分检测页和工件库页，并迁移相应状态测试。
4. 将几何规则管理器调整为完整页面，保持现有原图坐标、草稿 revision、验证、发布和回退契约。
5. 删除仅因本次迁移产生的旧入口、重复控件和失效样式，不清理无关代码。
6. 完成自动化回归与 1920×1080 人工视觉验收。

迁移期间优先保留现有 Qt Test 使用的关键 `objectName`、按钮语义和信号契约。不得一次性重写后端通信或几何坐标模型。

## 13. 风险与缓解

- **MainWindow 状态耦合**：先建立页面边界，再逐步移动状态；每一步运行相关 Qt 测试。
- **后端仅允许一个在途请求**：使用统一任务协调和明确忙碌原因，不伪造并行交互。
- **几何草稿与 revision 丢失**：页面切换不得销毁编辑状态；保存、验证、发布继续校验 revision。
- **画布坐标回归**：保持原图像素坐标到显示坐标的单一转换路径，增加缩放/平移回归测试。
- **旧 UI 测试大量依赖控件**：尽量保留对象名并分阶段迁移测试夹具。
- **高 DPI 与固定尺寸问题**：使用布局和可调分栏，避免新的固定大尺寸图片框。

## 14. 测试与验收

### 14.1 自动化测试

至少覆盖：

1. 一级页面导航与返回时状态保留；
2. 后端状态在所有页面同步且恢复操作一致；
3. 单张与批量模式互不污染当前结果；
4. 批量行与图片、证据、确认对象始终对应；
5. 批量筛选、自动前进和失败保留；
6. 任意、不等模板数量的编辑、建库和恢复；
7. 建库与异步入库跨页面进度；
8. 工件删除二次确认；
9. 单一逻辑规则在正反面均可见并分别保存标定；
10. 保存后默认显示拟合边界，手绘引导默认隐藏；
11. 一键保存、验证与发布的成功、阻断和重试路径；
12. 页面离开和窗口关闭时的脏状态保护；
13. 后端断开、超时、模型加载和重启时保留现场数据；
14. 旧版 5+5 工件库和已有规则版本继续恢复；
15. 现有 Python 与 Qt 回归测试继续通过。

### 14.2 人工视觉验收

在 Windows、Qt 5.14.2、1920×1080 和常用 DPI 缩放下检查：

- 无关键控件裁切、重叠或必须滚动才能完成主操作；
- 最终判定、复检状态和确认按钮具有最高视觉权重；
- 页面、对话框、表格、按钮、错误和进度使用统一样式；
- 长路径、长错误和大量模板不会破坏布局；
- 几何画布图例、拟合边界和问题定位清楚可辨；
- 仅使用键盘或鼠标时均可完成主要流程。

## 15. 成功标准

- 操作员启动应用后可在一个无滚动的主页面完成单张检测与人工确认；
- 工件维护和几何规则不再占据检测首页，也不会因页面切换丢失状态；
