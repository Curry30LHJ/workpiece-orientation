# 轻量几何快速推理设计

日期：2026-08-27  
分支：`feature/20260827/lightweight-geometry-fast-path`

## 1. 背景

当前生产推理同时使用几何规则、PP-ShiTu、ALIKED 和 LightGlue。真实 M1 单图预热基准约为：

- 总耗时 P50 约 229 ms，P95 约 238 ms；
- ALIKED 查询特征 P95 约 42 ms；
- LightGlue 局部匹配 P95 约 136 ms；
- 当前几何拟合与遮罩构建仍有数十毫秒开销。

因此，只减少 LightGlue 候选数无法满足甲方提出的在线单图 `P95 <= 25 ms`。另一方面，几何规则能有效表达“忽略内部反光”和“忽略外部侵入工件”，不能简单删除。

现有 PP-ShiTu 原图特征加每工件 Ridge 判别头的探索性结果为：当前 M1、M2、M7 的 266 张非模板图片达到 266/266，在线特征和判定约 5--7 ms。该结果支持建立快速路径，但不代表对所有新工件的准确率保证，因此必须保留逐工件验证门禁和可回滚能力。

## 2. 目标

1. 每张图片都执行轻量几何定位，并让已发布几何规则实际参与推理。
2. 正式在线路径不调用 ALIKED、LightGlue 或 ORB。
3. 使用一次 PP-ShiTu batch 和每工件 Ridge 判别头完成正反面判断。
4. 在当前 RTX 4060 Ti 工控机上，预热后的后端单图推理达到 `P95 <= 25 ms`。
5. 固定验收集相较当前完整流程不新增误判，建议复检比例不超过 5%。
6. 保持现有逻辑规则、正反面独立标定、内部/外部忽略、带符号边界偏移、发布和回滚语义。
7. 兼容旧工件库以及任意正整数、可不相等的正反模板数量。

## 3. 非目标

- 不重新训练或微调 PP-ShiTu。
- 不修改 PP-ShiTu 权重和输入定义。
- 不在在线结果中展示局部匹配点。
- 不承诺单张最大耗时不超过 25 ms；本次服务等级是 P95。
- 不在本变更中重构几何规则编辑器或其他无关 Qt 页面。
- 不立即删除旧 ALIKED/LightGlue 实现；它只保留为显式兼容、离线对照和回滚路径。

## 4. 性能口径

正式性能门禁使用以下固定口径：

- 硬件：当前 NVIDIA GeForce RTX 4060 Ti 工控机；
- 模型和工件库先完成加载，预热 50 次；
- 连续执行至少 1000 次单图检测；
- 统计从后端开始读取输入图片到结果对象构造完成的 wall time；
- 包含图片读取、预处理、轻量几何、遮罩、PP-ShiTu、Ridge 判定和结果组装；
- 不包含程序启动、模型首次加载、工件建库和 Qt 绘制；
- 主门禁为 P95 `<= 25 ms`，同时报告 mean、P50、P99 和 max；
- Qt 到后端的往返时间单独报告，不混入算法门禁。

## 5. 总体架构

在线数据流为：

```text
输入图片
  -> 共享轻量边界上下文
  -> 正面方向几何拟合 + 反面方向几何拟合
  -> 原图、正面遮罩图、反面遮罩图
  -> 一次 PP-ShiTu batch（batch size 3）
  -> 特征拼接与每工件 Ridge 判别头
  -> 正面 / 反面 + 置信度 + 是否建议复检
```

几何规则仍是一个用户可见的逻辑规则，正面和反面分别保存标定。查询方向未知时，两套标定都从同一个查询图生成候选处理图，最终由判别头比较，而不是先猜方向再选择规则。

没有已发布几何规则的工件编译为显式 no-op profile：正面和反面处理图均为原图副本，状态为 `not_configured`，不把“没有配置规则”误报为拟合失败。只要存在启用规则，对应方向就必须尝试轻量拟合。

## 6. 轻量几何运行时

### 6.1 编译阶段

几何规则发布或快速缓存重建时，将现有运行时 profile 编译成 `fast_geometry_v1`：

- 保留正反面独立 anchor、规则形状、模式和带符号偏移；
- 把对象相对坐标转换为紧凑数值数组；
- 预计算各支持形状的期望边界、候选搜索窗口和尺度范围；
- 记录 profile 修订、编译器版本和参数版本；
- 不改写作为事实来源的现有 geometry profile。

仍支持圆、椭圆和旋转矩形。编译结果只是派生缓存，可以随时从已发布 profile 重建。

### 6.2 查询图共享上下文

每张查询图只创建一次共享上下文：

1. 保持宽高比缩放，使长边不超过 256 像素；
2. 生成一张灰度图，并在该低分辨率图上执行一次 Canny 和轮廓提取；
3. 以图像中心附近的完整主体为先验，建立一次候选边缘上下文；
4. 正反方向复用同一上下文，禁止重复执行原图尺寸 Canny、轮廓枚举和无约束候选排序。

固定尺寸只用于拟合，最终边界和遮罩坐标按比例还原到原图。目标工件仍定义为最靠近画面中心、主体大部分完整可见的工件；四周侵入工件通过中心先验和稳健离群点剔除处理。

### 6.3 方向拟合

正反面继续独立拟合，但共享图像计算：

- anchor 只对落入已编译期望位置和尺度窗口的轮廓进行现有质量评分；
- 每条规则先由 fitted anchor 投影到查询图，再只评分其自身窄带窗口中的轮廓；
- 使用稳健拟合剔除反光、阴影和边缘侵入造成的孤立响应；
- 圆、椭圆和旋转矩形分别输出与现有 profile 等价的 fitted shape；
- 正反面可以选择不同边界，不能把一面的拟合结果直接复制为另一面结果；
- 低支持度、高残差或拓扑不合法时返回稳定的低置信度状态，不伪造边界。

候选窗口宽度、尺度范围和置信度阈值作为版本化内部常量，以真实数据基准选择；它们不作为首版 Qt 配置项，避免产生未经验证的现场参数组合。

首版不另写一套边界模型，而是复用已经通过现有模板验证的 `GeometryCalibrator` 候选拟合和质量门禁，只把它运行在共享的 256 像素上下文并预先过滤候选。现有实测中拟合约占 6 ms，主要几何开销来自 Telea 修复；该取舍优先保持当前边界语义和准确率。若这一实现不能通过 25 ms 门禁，应停在基准任务重新审查设计，而不是在同一变更中加入另一套未经验收的拟合器。

当某一方向拟合失败时，该方向的处理图使用原图副本以保持固定三图特征布局，同时记录 `FAST_GEOMETRY_LOW_CONFIDENCE`。系统不得把手绘 seed 或上一张图片的边界当作本张图片的有效拟合；本次结果必须进入复检。

### 6.4 遮罩构建

现有规则语义保持不变：

- `inside` 忽略有效边界内部；
- `outside` 忽略有效边界外部；
- 负偏移缩小几何边界，正偏移扩大几何边界；
- 多条规则取忽略区域并集。

在线不再使用 Telea inpaint。忽略区域使用与模板缓存一致的方向中性填充值，边界只做小范围羽化，避免产生可被分类器利用的硬边伪特征。模板和查询必须调用同一遮罩函数、同一填充值策略和同一版本参数。

## 7. 快速特征与 Ridge 判别头

### 7.1 在线特征

每张查询图构造三个输入：

1. 原图；
2. 应用正面标定规则的处理图；
3. 应用反面标定规则的处理图。

三张图通过一次 PP-ShiTu batch 提取 embedding。每个 embedding 独立 L2 归一化，然后按固定顺序拼接。判别头只进行一次向量点积和偏置相加，不遍历所有模板，也不执行局部匹配。

### 7.2 建库特征

建库或缓存重建时，每张模板也生成上述三组 embedding。正反模板数量允许不同，所有有效模板都参与拟合，不截断、不忽略。

模板较少时采用离线旋转增强：

- 只对少于 20 张的方向按 30 度步长生成旋转样本；
- 旋转围绕已拟合主体中心执行；
- 增强样本只用于 Ridge 拟合，不作为用户模板写回工件库；
- Ridge 使用类别平衡权重，避免正反原图数量或增强后数量不同造成类别偏置；
- 所有增强推理使用批处理，并在 Qt 中显示建库阶段和耗时；
- 当正反均达到 20 张时不再自动旋转增强，避免无意义增加建库时间。

该策略来自当前少样本交叉验证：5+5 的 M1 在 30 度增强后明显优于无增强方案。它不增加在线耗时。

### 7.3 判别头

每个工件保存一个二分类 Ridge 判别头：

- 标签固定为正面和反面；
- 使用稳定的闭式解，不进行神经网络训练；
- 正则化参数从固定小网格中通过建库样本的留一验证选择，平局时选择更强正则；
- 缓存保存权重、偏置、正则化值、特征维度、类别样本数和训练摘要；
- 1+1 也允许拟合，但因无法获得可靠留一统计，必须显示少样本风险并采用保守复检阈值；
- 正反样本数量不同不会改变特征维度，也不会导致预测路径依赖固定数量。

### 7.4 置信度与复检

当输入可读、快速缓存有效且 PP-ShiTu 输出有效时，结果给出预测方向和有符号 margin。以下任一情况设置 `needs_review=true`：

- 任一必要方向的轻量几何拟合低置信度；
- Ridge margin 低于该工件的验证阈值；

低置信度不会在同一个在线请求中启动 ALIKED、LightGlue 或 ORB。轻量几何失败时只要三图 batch 仍能产生有效 embedding，就返回方向建议和复检原因。快速缓存缺失、损坏、修订不一致，或者 PP-ShiTu 特征无效时，没有可信判别头可用，必须返回稳定错误而不是猜测方向。图片无法读取时继续按现有协议拒绝检测。

## 8. 快速缓存与兼容

新增派生缓存清单，至少绑定：

- 缓存 schema 和实现版本；
- 工件库 ID 与 library revision；
- 几何 profile revision；
- PP-ShiTu 模型指纹；
- 图像预处理和轻量几何版本；
- 正反模板路径、内容指纹和实际数量；
- Ridge 权重、阈值及训练摘要。

缓存采用临时修订目录构建并原子切换。构建失败不能覆盖最后一个有效缓存。

旧工件库保持可恢复：

- 后端启动先加载目录和已有可用缓存，不因快速缓存缺失而阻塞模型就绪；
- 缺失或过期的快速缓存在后台排队重建，并向 Qt 报告明确状态和进度；
- 缓存未就绪时不得静默使用旧权重；用户可以显式选择旧兼容流程，或等待快速缓存完成；
- 旧 5+5 工件库以及正反不等数量工件库无需重新采集模板；
- 删除工件时沿用现有删除事务，同时删除其派生快速缓存。

## 9. 运行模式与发布策略

提供三种显式模式：

- `legacy`：现有几何、PP-ShiTu、ALIKED、LightGlue 完整流程；
- `fast_geometry`：本设计的正式快速流程；
- `compare`：离线验收工具对同一输入分别执行两种流程并生成差异报告。

`compare` 不用于生产在线请求，避免影子计算争抢 GPU 并污染延迟。首次合入时保留当前默认模式；只有固定验收集的准确率、复检率和性能门禁全部通过，才把正式配置切换为 `fast_geometry`。切换和回滚都必须是显式配置变化，不根据单张输入静默改变算法。

## 10. 返回结果与 Qt 最小改动

后端结果增加但不破坏现有字段：

- `inference_engine`；
- `fast_cache_revision`；
- `geometry_status` 及正反方向拟合摘要；
- `decision_margin`；
- `needs_review` 和稳定原因码；
- `timings_ms.decode/geometry_context/geometry_fit/mask_build/global_batch/linear_head/total`。

Qt 只做与本功能直接相关的调整：显示当前推理引擎、快速缓存准备状态、复检原因和分段耗时。不增加局部匹配点界面，不顺带重构其他页面。

## 11. 错误处理

至少提供以下稳定错误或状态码：

- `FAST_CACHE_NOT_READY`：快速缓存正在构建或尚未构建；
- `FAST_CACHE_REVISION_MISMATCH`：缓存与工件库或 profile 不匹配；
- `FAST_CACHE_BUILD_FAILED`：后台构建失败，保留旧有效缓存；
- `FAST_GEOMETRY_LOW_CONFIDENCE`：轻量边界拟合不足，结果建议复检；
- `FAST_CLASSIFIER_LOW_MARGIN`：Ridge margin 不足，结果建议复检；
- `FAST_FEATURE_INVALID`：PP-ShiTu 输出缺失、维度或数值无效；
- `FAST_MODE_NOT_VALIDATED`：该工件尚未通过快速模式验证。

状态必须带可操作中文提示。不可读图片仍使用现有图片错误，不降级为猜测结果。

## 12. 测试设计

### 12.1 单元测试

- profile 编译保留圆、椭圆、旋转矩形及正负边界偏移语义；
- 正反面共享图像上下文但输出独立拟合；
- 内部、外部和多规则并集生成正确遮罩；
- 模板与查询使用完全相同的遮罩预处理；
- Ridge 支持 1+1、5+10、10+15、35+35 和正反不等数量；
- 所有模板均进入缓存和判别头输入，无固定数量假设；
- 缓存修订或模型指纹不匹配时拒绝使用；
- 在线快速路径的调用记录中没有 ALIKED、LightGlue 或 ORB；
- 低置信度只设置复检，不启动旧局部分支。

### 12.2 集成与兼容测试

- 旧 5+5 工件库恢复并在后台生成快速缓存；
- 快速缓存构建失败不损坏旧缓存，重试后可原子切换；
- 工件删除同时清理快速缓存；
- 几何规则发布或回滚使快速缓存失效并触发正确修订重建；
- Qt 显示准备中、可用、失败、需复检和兼容模式；
- `legacy`、`fast_geometry` 和 `compare` 模式可显式选择，不发生隐式切换。

### 12.3 准确率验收

- 对当前 M1、M2、M7 固定非模板验收集运行 legacy 与 fast 对照；
- fast 相较 legacy 不得新增误判；
- 建立中心反光、边缘侵入、旋转、偏移和不同裁剪尺寸分组报告；
- 总体 `needs_review` 比例不得超过 5%；
- 检查启用规则与关闭规则的特征或得分确有可解释差异，防止规则只显示但未参与计算；
- 任一门禁失败时，不切换正式默认模式。

### 12.4 性能验收

- 按第 4 节口径执行至少 1000 次连续单图检测；
- 输出原始逐次记录和 mean/P50/P95/P99/max；
- P95 必须不超过 25 ms；
- 分段报告必须能定位几何、遮罩或 PP-ShiTu 的预算超支；
- 分别记录 1+1、5+10、10+15、35+35 的建库总耗时、增强图片数和缓存大小；
- 性能测试失败不得通过减少测试样本、排除慢样本或修改统计口径规避。

## 13. 预计延迟预算

首轮目标预算如下，最终以实测为准：

| 阶段 | 目标 P95 |
| --- | ---: |
| 图片读取与基础预处理 | 1--3 ms |
| 共享轻量几何与双方向拟合 | 2--5 ms |
| 三张处理图遮罩构建 | 1--2 ms |
| PP-ShiTu batch size 3 | 6--10 ms |
| Ridge 与结果组装 | <1 ms |
| 预留抖动 | 3--5 ms |
| 总计 | 13--20 ms 工程目标，25 ms 验收上限 |

这只是工程预算，不作为成功证据。如果 batch size 3 或几何阶段实测超支，应先优化该阶段；不得通过恢复同步 LightGlue 复核来掩盖问题。

## 14. 实施顺序

1. 用测试固定缓存版本、三图 batch、Ridge 和“无局部模型调用”契约；
2. 实现离线快速缓存和 Ridge 判别头；
3. 实现轻量几何共享上下文、方向拟合和快速遮罩；
4. 接入 `fast_geometry`，保留显式 `legacy`；
5. 增加 Qt 最小状态显示和离线 `compare` 基准；
6. 运行准确率门禁，再运行 1000 次性能门禁；
7. 只有全部通过才切换默认配置，并保留一键回滚。

## 15. 验收标准

实现完成必须同时满足：

1. 新分支上的相关自动化测试全部通过；
2. 每张可读图片都尝试轻量几何，规则真实参与三图特征构造；
3. 正式在线路径不调用 ALIKED、LightGlue 或 ORB；
4. 固定验收集相较 legacy 不新增误判；
5. 建议复检比例不超过 5%；
6. 后端单图 P95 不超过 25 ms；
7. 旧库、任意正整数模板数和正反不等数量继续兼容；
8. 缓存错误不会静默产生错误结果；
9. 当前几何规则语义、发布和回滚能力保持不变；
10. 未通过门禁时默认配置保持旧流程。
