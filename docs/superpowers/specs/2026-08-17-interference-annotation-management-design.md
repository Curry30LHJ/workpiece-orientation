# 干扰标注管理器与递推审计设计

## 1. 评审结论

现有“标注干扰区域”功能只覆盖了新增一条矩形标注，没有形成完整的管理闭环：

- 不能重新打开并在原图上查看已经保存的区域；
- 干扰类型只有名称输入，没有稳定的类型列表、启停和删除入口；
- 自动递推只暴露最终状态，操作员看不到递推到了哪些模板、由哪些人工样本支持、为何失败；
- 编辑器一次只能绘制一个矩形，不能管理同一模板上的多个区域；
- 界面没有区分“编辑草稿”和“当前识别已经生效的版本”，容易让操作员误以为待复核标注已经参与预测；
- 删除若只在界面移除列表项，会留下清单、运行时掩码和预测缓存不一致的风险。

因此，本次完善不能只增加一个查看列表，而应建立“查看、编辑、递推审计、复核、启停、删除、原子生效”的标注管理闭环。

## 2. 目标与边界

本设计新增一个独立的“干扰标注管理器”，让操作员能够：

1. 查看当前工件的所有干扰类型及其生效状态；
2. 在模板原图上叠加查看人工区域和自动递推区域；
3. 查看每个模板的递推来源、置信度、失败原因和剩余局部特征情况；
4. 新增、重命名、停用、启用和删除干扰类型；
5. 对待复核结果执行接受、修正、拒绝或“该模板不存在此干扰”；
6. 明确知道当前看到的是编辑草稿还是已参与预测的生效版本。

本次不改变 PP-ShiTuV2、ALIKED、LightGlue、输入尺寸、模型权重或现有融合阈值，也不把少量矩形标注解释为语义模型训练。

## 3. Qt 交互设计

主界面在选中工件后提供“管理干扰标注”按钮。管理器采用三栏布局：

```text
+------------------+--------------------------+----------------------+
| 干扰类型          | 模板与递推状态            | 原图预览与诊断         |
|                  |                          |                      |
| 边缘反光  已生效   | 正面 1  人工/已生效        | [模板原图 + 区域叠加]   |
| 侵入工件  待复核   | 正面 2  自动/已生效        |                      |
| 阴影      已停用   | 反面 1  自动/待复核        | 来源、置信度、失败原因   |
|                  | 反面 2  已确认不存在        | 剩余关键点与面积占比     |
+------------------+--------------------------+----------------------+
| 新增  重命名  停用/启用  删除 | 接受  修正  拒绝  标记不存在  重新递推 |
+-----------------------------------------------------------------------+
```

### 3.1 干扰类型列表

每一项显示：名称、稳定 `group_id`、启用状态、传播状态、人工种子数、自动生效数、待复核数和未解析数。名称仅用于显示和编辑，所有修改与删除都以稳定 `group_id` 为准。

状态文字必须明确区分：

- `已生效`：该组当前版本已经参与本地特征过滤；
- `待复核`：存在尚未解决的模板，草稿未整体生效；
- `已停用`：组和历史标注仍保留，但不参与预测；
- `无有效种子`：可信人工样本不足两个，尚不能自动递推；
- `生效中/保存中`：后端正在构建候选缓存，旧稳定版本仍在预测。

默认提供“停用”作为可逆操作。删除是显式操作，确认框必须显示类型名称、受影响模板数以及“删除后该类型的人工与自动区域都会移除”。

### 3.2 模板状态矩阵

选中干扰类型后，按正面/反面列出所有模板。每个模板必须恰好呈现一种状态：

- 人工标注且已生效；
- 自动递推且已生效；
- 自动递推待复核；
- 操作员确认不存在该干扰；
- 已拒绝候选；
- 未解析。

列表显示模板序号、稳定模板标识、来源、状态、区域数量和最近更新时间。不能仅用颜色表达状态；文字和图标必须同时存在。

### 3.3 原图叠加预览

选中模板后加载工件库中实际保存的模板图，并绘制全部区域：

- 人工生效区域：绿色实线；
- 自动生效区域：蓝色实线；
- 待复核区域：橙色虚线；
- 当前选中区域：加粗边框并显示区域序号。

预览支持适应窗口和缩放。显示坐标始终由原图坐标映射而来；窗口缩放不能修改原始标注。图片缺失或无法读取时显示可诊断错误，不能让整个管理器崩溃。

编辑模式允许在同一模板、同一干扰类型下添加多个矩形，并选择、移动或删除单个矩形。切换模板、类型或关闭窗口前，如果存在未保存修改，必须提示保存、放弃或取消切换。

### 3.4 递推审计面板

每个自动候选必须展示以下可解释信息：

- 支持该候选的人工来源模板；
- 尝试来源数和成功投影数；
- 几何一致性置信度和最大投影分歧；
- 区域占目标图像的比例；
- 屏蔽前后保留的局部关键点数或保留比例；
- 决策结果与稳定原因码，例如“可信来源不足”“几何不一致”“区域过大”“剩余特征不足”“目标图片无法读取”。

界面同时显示“草稿传播状态”和“当前识别使用版本”。如果草稿处于待复核，必须明确显示“尚未参与预测，当前仍使用修订前的稳定掩码”。

### 3.5 待复核操作

对一个待复核模板，操作员可以：

- 接受：候选区域变为可信标注；
- 修正：在原图上调整区域后保存为可信标注；
- 拒绝：记录候选摘要，防止相同候选未经变化再次自动激活；
- 标记不存在：明确表示该模板没有此类干扰，而不是把“没有匹配到”误判为不存在；
- 重新递推：当人工种子发生变化后重新计算该组草稿。

只有一个启用组的所有模板都处于“已生效”或“已确认不存在”时，候选掩码才可以作为一个整体原子发布到预测缓存。

## 4. 后端数据与协议设计

### 4.1 查询快照

`get_workpiece_annotations` 返回一个完整、只读的一致快照，而不是只返回 `groups`：

- `workpiece_id` 和当前 `revision`；
- 正反面模板列表，每项包含稳定 `template_id`、方向、序号、预览路径和原图尺寸；
- 干扰类型列表及其 `enabled`、草稿状态和生效状态；
- 每个模板的区域、来源、状态和递推诊断；
- 当前识别缓存使用的标注修订号。

Qt 只渲染该快照，不在界面层推断递推状态。

### 4.2 修改命令

保留 `save_workpiece_annotations` 处理新增、重命名、区域编辑和复核结果，并补充：

- `set_workpiece_annotation_group_enabled`：可逆地停用或启用一个类型；
- `delete_workpiece_annotation_group`：删除一个类型及其全部人工、自动和拒绝记录。

所有修改命令必须携带 `operation_id` 和界面读取到的 `base_revision`。若后端修订号已经变化，返回 `STALE_WORKPIECE_REVISION`，Qt 刷新快照并要求操作员重新确认，不能用旧界面状态覆盖新标注。

删除、停用和编辑均在候选修订中完成。后端先验证标注、传播结果和安全约束，再一次性更新 manifest 与运行时模板缓存。任何失败都保留之前的稳定清单和预测缓存。

### 4.3 诊断字段

自动递推诊断使用稳定机器字段和中文展示文本分离的方式保存，至少包含：

- `reason_code`；
- `source_template_ids`；
- `attempted_source_count` / `successful_projection_count`；
- `confidence` / `max_spread_px`；
- `area_ratio`；
- `keypoints_before` / `keypoints_after` / `remaining_ratio`。

旧工件库没有这些字段时正常恢复，界面显示“旧版本未记录该诊断”，不能伪造为成功或失败。

## 5. 一致性与删除语义

- “删除类型”只删除当前工件中的该干扰组，不影响其他工件；
- 删除使用稳定 `group_id`，不能以可能重复或已修改的名称定位；
- 删除成功后，清单修订号递增，并用其余已生效组从未过滤的原始局部特征重新生成过滤缓存，确保被删除组的区域不再残留；
- 若重建或发布失败，删除操作整体失败，原类型和原预测缓存保持可用；
- 待复核草稿与当前生效版本必须分别保存和显示，不能把部分递推结果直接混入当前预测；
- 停用保留所有标注和诊断，重新启用时重新执行传播与安全检查；
- 旧版无标注工件打开管理器时显示空状态，可直接创建第一个类型。

## 6. 测试与验收标准

### 6.1 后端测试

- 查询能返回模板、类型、区域、来源、状态、诊断和当前修订的完整快照；
- 删除指定 `group_id` 后，其他类型和区域保持不变；
- 删除后预测缓存不再包含该组掩码；
- 删除期间发生校验或缓存发布失败时，清单与旧缓存均不变化；
- 使用过期 `base_revision` 的保存、停用和删除被拒绝；
- 相同 `operation_id` 重试返回同一结果，不重复递增修订号；
- 无标注旧工件和缺少新诊断字段的旧清单可以正常查询；
- 自动候选诊断包含来源、置信度、分歧、面积和剩余关键点信息。

### 6.2 Qt 测试

- 选中工件后可以打开管理器，未选工件或后端忙时按钮不可用；
- 已保存的人工、自动和待复核区域能在正确模板原图上按原生坐标重现；
- 类型列表和模板矩阵显示正确数量与状态；
- 选择不同模板会同步刷新预览和诊断；
- 删除必须二次确认，取消不发送请求，成功后刷新快照；
- 过期修订错误会刷新而不会覆盖服务端标注；
- 待复核候选可接受、修正、拒绝或标记不存在；
- 多矩形添加、选择和删除可用，未保存切换会提示；
- 模板图无法读取时显示错误占位而不崩溃。

### 6.3 完成定义

只有同时满足以下条件才视为完成：操作员能从主界面进入管理器；能在原图上查看每个已保存区域；能管理并删除干扰类型；能逐模板追踪自动递推的来源、结果和失败原因；删除或编辑不会留下 manifest 与预测缓存不一致；现有识别测试和 Qt 回归测试全部通过。

## 7. 实施顺序

1. 先补完整查询快照、修订校验和类型删除/启停领域接口；
2. 再实现 Qt 管理器的类型列表、模板矩阵、原图叠加和诊断面板；
3. 然后补多矩形编辑和待复核操作；
4. 最后执行后端、协议、Qt 和真实工件库兼容回归。

这个顺序保证每个界面操作都有明确的后端语义，不会先做出一个只能展示、无法保持数据一致性的界面。
