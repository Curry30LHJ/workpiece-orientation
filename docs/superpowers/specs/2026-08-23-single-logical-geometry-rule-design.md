# 单一逻辑几何干扰规则与双方向标定设计

日期：2026-08-23
状态：待用户审阅
适用项目：`workpiece-orientation` / `pp_813`

## 1. 目标

将现有“正面一套规则、反面另一套规则”的几何干扰规则模型，重构为：

- 用户只创建和管理一条逻辑规则；
- 同一条逻辑规则分别保存正面、反面两套独立标定结果；
- 推理时不知道输入方向，因此同时执行正面分支和反面分支预处理，再分别与对应方向模板比较；
- 手绘图形只用于引导边界搜索，程序拟合出的边界才进入运行时预测；
- 规则列表、边界显示、验证结果和发布流程保持一致、可解释、可回退。

本设计同时修复当前 Qt 管理界面中以下已复现问题：

1. 点击不同验证模板后，左侧规则列表会消失或出现重复规则；
2. 左侧没有选中规则时，画布仍显示某条边界；
3. 保存草稿后重新显示手绘虚线，而不是程序拟合边界；
4. 正面创建规则后，反面只能依靠“复制到另一方向”，复制又产生重复规则；
5. 验证表显示“候选 -1、支持 0”，但模板实际状态为已通过；
6. 界面预览显示的拟合边界正确，但保存到 profile 的却仍是手绘粗略边界；
7. 规则发布步骤多、状态含义不清，且旧规则迁移可能发生静默合并或丢失。

## 2. 不在本次范围内

本次不修改：

- PP-ShiTu、ALIKED、LightGlue 模型及其权重；
- 现有融合阈值、置信度阈值和正反面决策阈值；
- 模板数量策略、模型训练流程和模板特征提取算法；
- 工件图像裁剪方式；
- 当前已发布 v1 规则在新 v2 规则发布前的运行行为。

## 3. 现状证据与根因

### 3.1 实际规则数据不对称且存在重复

运行库 `31f082d1a04e486b9345846f4d585033` 的 `geometry_masks/profile.json` 当前为 schema v1：

- 正面规则数：0；
- 反面规则数：4；
- 反面包含两条“中心反光”和两条“四周侵入”；
- 其中两条“四周侵入”的几何半径近似相同。

因此，当前界面点击正面模板时规则列表为空，点击反面模板时显示 4 条规则，并非随机刷新问题，而是 UI 直接展示了方向私有规则数组。

### 3.2 规则列表错误绑定模板方向

Qt 的规则刷新逻辑按当前方向读取规则。验证表前半部分是正面模板、后半部分是反面模板，点击行会切换方向，继而更换左侧规则集合。这违反“一个逻辑规则跨正反两面”的业务含义。

### 3.3 “复制到另一方向”制造了新规则

当前复制操作会为副本生成新的 `rule_id`。它不是给同一规则补充反面标定，而是在另一方向创建另一条规则。多次复制后，规则数量和语义都会重复。

### 3.4 未选规则时错误回退到第一条验证结果

画布加载当前模板的拟合边界时，在 `rule_id` 为空的情况下会接受验证结果中的第一条规则。因此可能出现“左侧没有规则，右侧却显示绿色边界”。

### 3.5 手绘引导线被跨模板重放

当前 dirty 草稿会把保存的粗略图形重新设为画布引导图形。切换模板后，这条只属于原编辑上下文的虚线也会被显示，造成超大圆、位置错误以及“程序拟合退化”的错觉。

### 3.6 验证表读取了错误层级的指标

候选编号、边缘支持度和残差属于模板验证结果中每条规则的嵌套诊断项，当前表格却从模板行顶层读取。因此模板总体已通过时，仍可能显示 `candidate=-1`、`support=0`。

### 3.7 保存的是手绘种子，而不是拟合结果

当前标定器生成 profile patch 时，用手绘 seed 计算相对几何，而不是用已选中的拟合候选计算相对几何。真实模板 `back:25.png` 已复现：

- 界面所选拟合相对半径约为 `0.949347`；
- profile patch 保存的相对半径约为 `1.344673`；
- 两者不相等。

这是当前边界在验证、保存和预测之间不一致的核心缺陷。

## 4. 采用的架构

采用 schema v2，将“规则定义”与“方向标定”分离。

### 4.1 逻辑规则 `LogicalRule`

一条用户可见、跨正反面的干扰规则。公共字段只保存一次：

- `rule_id`：稳定 UUID；
- `name`：规则名称；
- `shape`：用户选择的引导形状类型；
- `mode`：`ignore_inside` 或 `ignore_outside`；
- `margin_ratio`：有符号边界偏移比例；
- `margin_semantics`：固定为 `signed_geometric_offset`；
- `enabled`：规则是否参与运行时预处理。

公共字段的新增、删除、重命名、启停、内外模式和边界偏移，均只操作一次，不随正反面切换。

### 4.2 方向标定 `DirectionCalibration`

同一逻辑规则在 `front` 和 `back` 下各有独立标定：

- `geometry`：程序选中的拟合边界，相对拟合锚点存储；
- `seed_geometry`：用户手绘的粗略搜索范围，仅供编辑和重新标定；
- `reference_template`：建立该方向标定所用模板；
- `state`：`missing`、`ready`、`low_confidence` 或 `needs_review`；
- `diagnostics`：候选、边缘支持度、残差和选择原因；
- `updated_at`：最近标定时间。

正面和反面的边界可以不同，互不复制像素坐标，也不要求共用拟合参数。

### 4.3 模板审阅 `TemplateReview`

模板验证状态属于方向和模板，不属于逻辑规则清单。每个模板保存：

- 总体状态：`pending`、`passed`、`warning`、`failed`；
- 每条逻辑规则的嵌套拟合结果；
- 人工处置状态和原因；
- 使用的 profile 修订号。

### 4.4 Seed 与 Fitted Geometry 的强约束

系统必须遵守：

```text
seed_geometry 只定义“到哪里搜索”
geometry      才定义“预测时忽略哪里”
```

`seed_geometry` 绝不参与运行时遮罩生成。保存、验证、发布和预测必须使用程序选中的 `geometry`。如果不存在有效 `geometry`，该方向标定不得进入可发布状态。

## 5. schema v2

概念结构如下：

```json
{
  "schema_version": 2,
  "library_revision": 7,
  "draft_revision": 12,
  "active_revision": 11,
  "rules": [
    {
      "rule_id": "stable-uuid",
      "name": "中心反光",
      "shape": "circle",
      "mode": "ignore_inside",
      "margin_ratio": -0.04,
      "margin_semantics": "signed_geometric_offset",
      "enabled": true
    }
  ],
  "directions": {
    "front": {
      "anchor": {},
      "fill_bgr": [255, 255, 255],
      "calibrations": {
        "stable-uuid": {
          "state": "ready",
          "geometry": {},
          "seed_geometry": {},
          "reference_template": "front:00.png",
          "diagnostics": {},
          "updated_at": "2026-08-23T00:00:00+08:00"
        }
      },
      "template_reviews": {}
    },
    "back": {
      "anchor": {},
      "fill_bgr": [255, 255, 255],
      "calibrations": {},
      "template_reviews": {}
    }
  },
  "migration": {
    "source_schema_version": 1,
    "conflicts": []
  }
}
```

约束：

- `rules[].rule_id` 全局唯一；
- `calibrations` 的键必须引用现存逻辑规则；
- `geometry` 必须由选中的拟合候选生成；
- `seed_geometry` 可以不存在，但不能代替 `geometry`；
- `margin_ratio > 0` 表示几何边界向外扩张，`margin_ratio < 0` 表示向内收缩；
- 内部忽略和外部忽略均使用同一有符号几何偏移语义；
- 删除逻辑规则时，同时删除两个方向中对应的 calibration 和关联审阅数据；
- 禁止孤儿 calibration 和重复 `rule_id`。

运行时可将 `LogicalRule + DirectionCalibration` 物化为现有标定器所需的单方向 profile，从而尽量不改动底层几何算法接口。

## 6. 标定与保存流程

### 6.1 手动编辑

编辑上下文由四元组唯一确定：

```text
(rule_id, direction, template_id, draft_revision)
```

用户在某一模板上手绘圆、椭圆、矩形或多边形时，图形只属于这一编辑上下文。切换方向、模板、规则或修订号后，不得把该虚线重放到新上下文。

### 6.2 拟合预览

后端接收逻辑规则、方向、模板和 seed：

1. 在 seed 限定的区域内寻找真实边界；
2. 拟合锚点和候选边界；
3. 对候选进行排序；
4. 返回选中候选、其他候选和诊断信息；
5. Qt 仅预览程序拟合边界，不修改已发布 profile。

### 6.3 保存草稿

保存必须是原子操作：

1. 从选中拟合候选生成相对 `geometry`；
2. 将原手绘图形另存为 `seed_geometry`；
3. 保存候选诊断和参考模板；
4. 将该方向 calibration 标记为 `ready` 或需要人工处置的状态；
5. 增加草稿修订号；
6. 保存完成后清除手动编辑态。

严禁再次从 seed 生成运行时 `geometry`。拟合失败、置信度不足或 profile patch 为空时，不得写入部分 calibration。

## 7. 推理流程

输入图片的正反面未知，因此不得先根据某个方向的规则预处理后再决定方向。

对同一输入并行构造两个逻辑分支：

```text
原图
 ├─ front 标定规则预处理 ─> 仅与 front 模板比较 ─> front_score
 └─ back  标定规则预处理 ─> 仅与 back  模板比较  ─> back_score

front_score 与 back_score 进入现有融合与阈值决策
```

要求：

- 两个分支使用同一组逻辑规则，但各自使用本方向 `geometry`；
- 模板缓存也按方向使用相同物化规则生成；
- 正反面模板数量可以不同；
- 不增加方向预分类器；
- 不修改现有模型和融合阈值；
- 结果诊断必须记录每个方向使用的 profile 修订号和预处理状态。

### 7.1 安全回退

当任一启用规则在任一方向发生以下情况时：

- 缺少方向 calibration；
- 查询图拟合失败；
- 几何越界或有效面积不安全；
- profile 修订或缓存不一致；

本次几何规则增强整体回退到原始基线预测，并标记 `needs_review`。不得只对一个方向启用规则后直接与另一个原图分支比较，避免引入不可比的分数偏差。

## 8. Qt 交互设计

### 8.1 单一规则列表

左侧始终显示全局逻辑规则列表。点击正面或反面模板行只改变当前标定上下文，不改变规则条数、顺序或身份。

每条规则显示双方向状态，例如：

```text
中心反光 [启用]  正面：就绪  反面：待标定
```

### 8.2 操作语义

- “新增规则”：创建一条逻辑规则，两个方向初始均为待标定；
- “删除规则”：一次删除逻辑规则及正反两套标定；
- “重命名、模式、边界偏移、启停”：修改公共定义；
- 方向选择器：只切换标定分支；
- 删除“复制到另一方向”；
- 同一规则应在正面标定一次、反面标定一次。

### 8.3 画布显示状态机

画布不得根据“第一条报告规则”猜测要显示的边界。

| 状态 | 显示内容 |
|---|---|
| 未选规则 | 清除规则相关覆盖层 |
| 当前上下文正在手绘 | 仅显示当前手绘虚线和实时引导 |
| 拟合预览成功 | 显示程序拟合边界，并区分候选与选中项 |
| 草稿已保存 | 隐藏手绘虚线，仅显示已保存的程序拟合边界 |
| 验证模板已选择且规则已选择 | 显示该模板下该逻辑规则的拟合边界 |
| 该方向未标定或该规则无报告 | 不显示边界，给出明确状态文本 |

绿色或其他“有效边界”必须来自当前 `(rule_id, direction, template_id/revision)` 的精确匹配；禁止 `rule_id` 为空时回退到第一条规则。

### 8.4 验证表与诊断

模板表只显示模板总体字段：

- 方向；
- 模板名；
- 总体状态；
- 需要处理的规则数。

候选编号、边缘支持度、拟合残差、选择原因等放在当前选中逻辑规则的诊断面板中，并从 `template_review.rules[rule_id]` 读取。没有选中规则时，不显示伪造的 `-1` 或 `0`。

### 8.5 发布简化

保留一个主操作“保存、验证并发布”：

1. 保存当前拟合草稿；
2. 验证两个方向及所有模板；
3. 无阻断问题则原子发布；
4. 若缺少标定，自动切换到缺失方向和建议模板；
5. 若存在低置信度或迁移冲突，定位对应规则和模板，显示可执行的处理动作。

高级用户仍可保留分步入口，但主流程不得要求用户重复执行两个“保存草稿”动作。

## 9. v1 兼容与迁移

### 9.1 兼容原则

- loader 同时支持 schema v1 和 v2；
- 当前 active v1 profile 在 v2 草稿验证并成功发布前继续运行；
- 创建或迁移 v2 草稿不得修改 active v1 文件；
- v2 发布采用新修订号并保留回滚点；
- 回滚可恢复上一版 active profile 和对应缓存。

### 9.2 自动配对顺序

迁移器按以下顺序尝试把 v1 正反规则配为一条 v2 逻辑规则：

1. 正反两边具有相同且唯一的旧 `rule_id`；
2. 语义签名唯一匹配：规范化名称、shape、mode、margin 和 enabled 相同；
3. 其余情况不自动配对。

像素 geometry 不参与跨方向“相同”的判定，因为正反面边界本来可以不同。

### 9.3 冲突处理

以下情况生成 `migration.conflicts` 并阻断 v2 发布：

- 同一方向有语义重复规则；
- 一个规则可匹配多个另一方向规则；
- 只有单方向规则，另一方向缺失；
- 旧 `rule_id` 冲突；
- 规则内容不完整或 geometry 无效。

系统不得静默合并、覆盖、删除或任选一条。Qt 显示原规则来源和两方向状态，要求用户明确：

- 保留哪一条；
- 合并为哪一条逻辑规则；
- 删除哪一条重复规则；
- 为缺失方向重新标定。

现有 `front=0/back=4` 数据迁移时，应形成带缺失正面标定和重复冲突的 v2 草稿；active v1 继续工作，直到用户处理完冲突并发布。

## 10. 验证与发布门禁

一条启用的逻辑规则只有在下列条件全部满足时可发布：

- 正面 calibration 为 `ready`；
- 反面 calibration 为 `ready`；
- 两边 `geometry` 均来自已选程序拟合候选；
- 不存在未解决迁移冲突或重复逻辑规则；
- 所有纳入验证的模板具有可接受结果或已记录人工处置；
- 边界偏移后的有效区域满足现有安全条件；
- 模板缓存已使用待发布修订构建完成；
- 缓存修订号与待发布 profile 一致。

发布步骤：

1. 在新修订目录写入 v2 profile；
2. 构建并校验新修订缓存；
3. 运行发布前验证；
4. 原子切换 active 指针；
5. 失败时删除或隔离未完成修订，不改变当前 active。

## 11. 错误码与可操作提示

后端至少提供以下稳定错误码：

- `MISSING_DIRECTION_CALIBRATION`：启用规则缺少正面或反面标定；
- `NO_SELECTED_RULE`：请求需要规则，但 Qt 未提供 `rule_id`；
- `FITTED_GEOMETRY_MISSING`：拟合未产生可保存 geometry；
- `GEOMETRY_CONTEXT_MISMATCH`：结果与当前规则、方向、模板或修订不匹配；
- `MIGRATION_CONFLICT`：v1 规则无法安全自动配对；
- `DUPLICATE_LOGICAL_RULE`：存在同义或同 ID 规则；
- `PROFILE_CACHE_REVISION_MISMATCH`：profile 与模板缓存修订不一致；
- `GEOMETRY_FALLBACK_TO_BASELINE`：本次预测已安全回退基线。

Qt 必须把错误码转换为下一步动作，不能只显示 `Internal server error`。

## 12. 测试计划

### 12.1 Python 单元测试

- v2 schema 正常读写及约束校验；
- `LogicalRule + front/back calibration` 正确物化为两个方向 profile；
- 保存结果使用 selected fitted geometry，而不是 seed geometry；
- seed 与 fitted 半径不同的回归测试必须断言 profile 保存 fitted 值；
- v1 唯一匹配可自动迁移；
- v1 同方向重复、歧义匹配和缺失方向产生冲突，且不静默丢失；
- v1 active 在 v2 发布前不变；
- 删除逻辑规则同时删除两个方向 calibration；
- 推理同时执行正反分支，不依赖预先方向标签；
- 任一方向失败时整体回退基线并标记 review；
- profile/cache 修订不一致时拒绝增强预测。

### 12.2 Qt 单元测试

- 点击正面第一行和反面最后一行，左侧逻辑规则清单完全一致；
- 当前 `rule_id` 为空时画布不显示任意规则边界；
- 保存草稿后手绘虚线消失，显示保存的 fitted boundary；
- 切换模板不会重放其他模板的 seed；
- 选择规则后只显示精确匹配的嵌套诊断；
- 模板表不从错误层级读取 candidate/support/residual；
- 新增一次得到一条逻辑规则和两个待标定分支；
- 删除一次同时移除正反标定；
- 不再提供“复制到另一方向”；
- 缺少反面标定时主按钮自动定位反面，而不是创建副本；
- 迁移冲突可见、可定位、可处置，未处置时发布按钮说明明确。

### 12.3 集成测试

- 恢复旧版 v1 工件库并继续预测；

### 12.4 真实缺陷回归

必须固化以下两个红灯用例：

1. 当前 profile 的 `front=0/back=4` 数据：点击验证表任意正反模板行，逻辑规则清单身份和数量不得变化；
2. 构造 seed 相对半径约 `1.344673`、selected fitted 相对半径约 `0.949347` 的标定：保存后的运行时 geometry 必须等于 fitted 值，且 seed 只能出现在编辑溯源字段。

## 13. 验收标准

完成实现后必须同时满足：

1. 用户只看到并管理一份逻辑规则列表；
2. 每条启用规则明确显示正面和反面两套独立标定状态；
3. 点击任意模板不会改变逻辑规则清单；
4. 未选规则时不显示任何猜测边界；
5. 保存后显示程序拟合边界，不显示已结束编辑的手绘虚线；
6. profile 中运行时 geometry 与用户确认的拟合候选完全一致；
7. 正反面使用同一逻辑规则身份，但允许边界完全不同；
8. 推理在未知方向下执行两个方向分支，再进入现有分数比较；
9. 旧 v1 active 在 v2 成功发布前持续可用；
10. 重复、缺失或歧义旧规则不会被静默合并或删除；
11. 发布主流程可由一个“保存、验证并发布”操作完成；
12. 全部新增回归测试和现有相关测试通过；
13. 模型、权重和融合阈值没有变化。

## 14. 实施边界

后续实施应保持外科式修改：

- 先用测试固定上述两个真实红灯；
- 再引入 v2 profile 与迁移层；
- 再改标定保存语义和双分支运行时物化；
- 最后改 Qt 状态模型与简化发布流程；
- 不在本变更中顺带重构模型推理、模板建库或无关 UI。
