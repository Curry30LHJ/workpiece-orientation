# 持久化模板特征缓存设计

## 目标

缩短后端重复启动时的恢复时间，同时保持现有 PP-ShiTuV2、ALIKED/LightGlue 和融合阈值不变。模型初始化仍在启动阶段完成；工件模板特征在第一次建立或模板发生变化时计算，后续启动直接复用有效缓存。

## 设计

每个活动工件目录保存一个隐藏的 `.template_cache.pkl`。缓存由 `OrientationClassifier` 负责序列化，因为其中同时包含 NumPy 全局向量和 CPU 上的 ALIKED 特征字典。缓存元数据包含格式版本、特征配置（关键点上限和 ROI 比例）、正反面模板顺序、复制后文件名以及解码图像指纹。

`WorkpieceLibrary.recover` 接收可选的缓存加载/保存回调。回调命中有效缓存时跳过 `build_template_cache`；缓存不存在、签名不一致或反序列化失败时回退到完整重建，并在成功后原子写入新缓存。缓存错误不会使有效工件被跳过。

注册、追加模板和恢复回收区工件后都保存缓存。干扰区域标注仍通过现有 `raw_local_features` 重新应用，不把标注区域写进模板签名，因此标注变更不会触发昂贵的原始特征重算。

## 启动行为

TCP 监听和 Qt loading/ready 状态保持不变。模型加载期间业务请求继续返回 `MODEL_LOADING`；恢复完成后才允许预测和建库。缓存命中只缩短恢复阶段，不改变 ready 的安全边界。

## 兼容性与错误处理

- 旧版没有 `.template_cache.pkl` 的工件库继续按原流程重建。
- 缓存格式版本或特征配置变化会自动失效并重建。
- 缓存损坏、权限错误或指纹不匹配只记录警告，不影响工件恢复。
- 缓存写入采用临时文件加 `os.replace`，避免留下半写入文件。

## 验收

- 有效缓存恢复不调用特征构建器。
- 缓存缺失、损坏和模板内容变化会调用一次完整构建并生成新缓存。
- 旧版 5+5 工件库可以恢复。
- 正反面模板数量不等时签名和缓存恢复均正常。
- 现有 Python、Qt 测试保持通过。
