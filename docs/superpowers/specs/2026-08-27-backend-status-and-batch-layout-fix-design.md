# Qt 后端状态稳定化与批量结果响应式布局设计

## 1. 背景

当前 Qt 主窗口已经完成检测工作台、工件库和几何规则的一级页面重构，但实际运行中仍有两个可见问题：

1. 应用启动后，右上角后端状态会在“未连接”和“正在加载”之间反复跳变，直到后端最终连接成功；
2. 在约 `1085×752` 的窗口中进入批量检测结果页时，结果标题、证据、确认按钮和五列表格被同时压入约 400 px 的结果栏，出现拥挤、表格过矮和水平滚动条。

后端最终能够正常连接，说明本次不需要调整后端启动、模型加载或重试策略。问题一来自 Qt 展示层把一次自动重连过程中的瞬时 `Connecting`、`Error` 和 `Disconnected` 状态直接呈现给用户；问题二来自检测页只按固定 `65:35` 比例布局，并且现有视觉验收只覆盖了宽屏单张检测状态。

## 2. 目标

1. 自动启动和重连期间只显示稳定、可理解的生命周期状态，不展示 500 ms 重试产生的瞬时抖动；
2. 后端最终就绪、模型加载、业务处理中和终止性错误仍能被准确区分；
3. 在 `1024×640`、约 `1085×752` 和 `1920×1080` 下，批量检测的汇总、筛选、结果表、选中结果详情和人工确认都可见且可操作；
4. 点击批量结果行后，左侧图片、右侧证据和确认对象继续保持同一记录；
5. 保持 Qt 5.14.2、现有对象名、信号协议和检测业务行为兼容。

## 3. 非目标

- 不修改后端进程启动参数、500 ms 重试间隔或启动超时；
- 不修改 `BackendClient` 的网络协议、请求串行化或超时语义；
- 不修改 PP-ShiTu、ALIKED、LightGlue、几何规则、融合阈值或预测结果；
- 不把批量检测拆成新的一级页面；
- 不重写整个主题或其他页面布局。

## 4. 后端状态展示模型

### 4.1 单一展示入口

`MainWindow` 继续负责跨页面后端状态，但所有后端状态事件必须先归并为一个展示阶段，再统一更新 `AppHeader`、检测页、工件库页和几何规则页。事件处理函数不得再各自直接用瞬时客户端状态覆盖右上角摘要。

展示阶段至少包括：

- `Starting`：应用正在启动后端或首次建立连接；
- `LoadingModel`：服务已经响应，但模型仍在加载；
- `Ready`：后端可接收业务请求；
- `Busy`：已有业务请求正在执行；
- `Recovering`：曾经成功连接，随后连接中断，后台正在恢复；
- `Unavailable`：启动超时、进程退出、协议失败等终止性错误。

该阶段只属于 Qt 展示和页面可用性协调，不改变 `BackendClient::State`。

### 4.2 状态优先级

首次启动期间的自动连接尝试遵守以下规则：

1. 构造时存在 `BackendProcessManager`，进入 `Starting`；
2. `Connecting`、`Handshaking`、预期的连接失败和随后产生的 `Disconnected` 都保持 `Starting`，仅更新详情面板中的最近连接信息；
3. 收到 `MODEL_LOADING` 时进入 `LoadingModel`；
4. 握手成功时进入 `Ready`；
5. 只有 `backendUnavailable` 所代表的启动超时、进程失败或不可恢复握手错误才进入 `Unavailable`。

曾经成功连接后的断线不伪装成首次启动：

- 有在途操作时继续沿用现有“结果未知/保留现场”处理；
- 摘要进入 `Recovering` 或 `Unavailable`，自动重连产生的 `Error → Disconnected → Connecting` 不得反复覆盖摘要；
- 再次握手成功后回到 `Ready`。

无 `BackendProcessManager` 的测试或外部后端模式保持直接映射：客户端错误可以直接进入 `Unavailable`。

### 4.3 用户可见文案

| 展示阶段 | 顶部摘要 | 详情面板重点 |
| --- | --- | --- |
| Starting | 后端：正在启动 | 当前连接尝试和启动说明 |
| LoadingModel | 后端：模型加载中 | 后端返回的加载消息 |
| Ready | 后端：已连接 | 连接和模型均已就绪 |
| Busy | 后端：处理中 | 当前命令 |
| Recovering | 后端：正在重连 | 最近一次连接错误 |
| Unavailable | 后端：不可用 | 终止原因和“重启后端”入口 |

状态稳定不依赖延迟或防抖计时器，避免用视觉延迟掩盖错误的状态来源。

## 5. 批量检测响应式布局

### 5.1 主分栏

- 首次显示或进入批量模式时，结果栏建议宽度取“可用宽度的 35%”与 `440` 个逻辑像素中的较大值；因此宽屏保持约 `65:35`，窄屏会自然接近 `56:44`；
- 图片查看器继续保持最小可用尺寸，分栏仍可由用户拖动；
- `440` 是 Qt 布局使用的逻辑像素，不随 Windows DPI 缩放重复放大；
- 仅在首次显示、首次进入批量模式或当前布局已经无法满足最小可用宽度时应用建议比例，不在普通尺寸变化时覆盖用户手动拖动结果。

### 5.2 批量信息层级

批量模式中的垂直顺序调整为：

1. 批次汇总和进度；
2. 两行筛选按钮；
3. 批量结果表；
4. 当前选中记录的判定、证据和人工确认。

结果表和详情继续使用可拖动的竖向分隔条，默认给结果表更多高度。单张检测不显示批量表格，其结果详情行为保持不变。

### 5.3 紧凑结果详情

- 结果栏实际宽度低于 `520` 个逻辑像素时启用紧凑模式：结果标题使用紧凑字号，但仍是最高视觉权重；
- 文件名保持单行省略，完整路径和状态放入工具提示；
- 原始证据默认折叠；
- “确认正面”“修正为反面”“不入库”改为一行三个按钮，保持预测方向对应按钮为唯一主按钮；
- 详情区不得把结果表压缩到只能看到一行记录。

### 5.4 表格列

表格内部仍保留五列数据和现有稳定记录 ID：

1. 文件；
2. 结果；
3. 复检；
4. 耗时；
5. 处理状态。

紧凑模式下暂时隐藏低优先级的“耗时”列，耗时仍可在原始证据中查看；结果栏恢复到 `520` 个逻辑像素或以上后自动显示。其余列按可用宽度伸缩，批量主流程不应出现水平滚动条。

## 6. 数据与交互保持

- 不改变 `InspectionRecord`、批量筛选、确认入库、自动前进和失败保留逻辑；
- 表格行选择继续通过记录 ID 驱动，不使用可变行号作为业务身份；
- 响应式重排只改变控件布局和列可见性，不清空当前选择、图片或证据；
- 用户拖动分隔条后，普通重绘不得重置其位置；模式切换时可以恢复各模式的合理默认比例。

## 7. 测试与验收

### 7.1 后端状态回归

新增 Qt 测试模拟：

1. `Connecting → Error → Disconnected → Connecting` 的首次启动序列，顶部摘要始终为“正在启动”；
2. 首次启动期间 `MODEL_LOADING` 显示“模型加载中”；
3. 最终握手成功只显示“已连接”；
4. 启动超时或进程失败显示“不可用”和明确原因；
5. 已连接后的断线不会重新出现“未连接/正在加载”跳变，并能恢复到“已连接”；
6. 无进程管理器模式仍能直接报告客户端错误。

### 7.2 批量布局回归

新增批量页面夹具并在至少以下窗口尺寸验证：

- `1024×640`；
- `1085×752`；
- `1920×1080`。

检查：

- 汇总、筛选、结果表和确认按钮位于窗口内；
- 结果表具有可用高度并可看到多行；
- 窄栏无水平滚动条，耗时列按规则隐藏；
- 宽屏恢复耗时列；
- 点击表格行后图片、文件名、证据和确认对象一致；
- 单张检测布局和现有键盘焦点顺序不回归。

### 7.3 完整验证

- 运行相关 Qt 单测并运行完整 Qt 测试集；
- 运行现有 Python 测试；
- 构建 Release；
- 生成窄屏批量检测和宽屏单张检测截图进行人工视觉检查。

## 8. 成功标准

- 正常冷启动期间顶部状态不再闪烁；
- 最终连接结果、真正的启动失败和运行中断线均被准确表达；
- 用户截图对应尺寸下，批量结果区没有控件重叠、标题挤压、单行表格或水平滚动条；
- 本次修改不改变后端启动耗时、推理耗时、模型结果和既有工件库数据。
