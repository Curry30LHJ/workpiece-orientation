# CPU 推理路径优化设计

日期：2026-08-30
分支：`feature/20260830/cpu-inference-optimization`

## 1. 背景与问题

当前轻量快速路径在 GPU 上已经满足在线延迟目标，但 CPU 版本的热推理仍约为 176 ms（P95 约 222 ms）。基准显示，PP-ShiTu 全局特征提取占据绝大部分耗时；解码、几何处理和 Ridge 判定不是主要瓶颈。

输入在快速路径中固定生成三个语义槽位：原图、正面几何处理图和反面几何处理图。没有启用几何规则时，三个槽位像素完全相同，但当前实现仍重复执行三次特征提取。这是一个不改变分类语义、可以在 CPU 侧安全消除的重复工作。

## 2. 目标

1. 降低 CPU 热推理延迟，优先消除完全相同输入槽位的重复 PP-ShiTu 推理。
2. 保持现有分类结果、特征排列、几何规则和融合阈值不变。
3. 保持旧版 5+5 工件库、正反面不等模板数量和已有缓存格式兼容，无需重新建库。
4. GPU 路径默认保持当前行为，不因 CPU 优化引入额外延迟。
5. 提供可控的 CPU OneDNN 线程配置，并用固定基准选择默认值，避免过度并行导致尾延迟恶化。
6. 通过自动化测试和真实 CPU 基准报告验证收益；`P95 <= 25 ms` 作为持续目标，第一阶段不在未实测的情况下作出保证。

## 3. 非目标与不变项

- 不重新训练、微调或替换 PP-ShiTu 权重。
- 不改变 PP-ShiTu 的输入尺寸、预处理语义或特征向量格式。
- 不修改几何规则拟合、边界偏移、内部/外部忽略语义和正反面融合阈值。
- 不在本变更中引入 ONNX/OpenVINO/INT8 或更小模型；这些属于后续独立评估。
- 不删除 ALIKED、LightGlue 或 ORB 的兼容/回退代码。
- 不在后端启动时自动执行线程搜索。

## 4. 方案与架构

### 4.1 槽位去重

在 `FastOrientationEngine.predict()` 中，几何处理完成后、调用 embedder 前增加一个 CPU 可控的去重步骤：

1. 对每个槽位记录 shape、dtype、字节长度，并进行像素内容等值判断。
2. 只有 shape、dtype 和所有像素完全一致时才视为同一图像；不做近似比较、感知哈希或位置假设。
3. 生成 `unique_images` 与 `slot_to_unique` 映射，只将唯一图像传给 PP-ShiTu。
4. 对返回的唯一 embedding 按映射恢复为原来的三个槽位顺序，再进入既有拼接和 Ridge 判定。
5. 任意槽位无法安全比较时，记录包含 raw/front/back 槽位语义、shape、dtype、字节长度和原因的诊断信息，并回退到原三槽位路径，不能静默改变结果。

去重默认只对 CPU 生效，由 `OrientationClassifier.load()` 根据 `compute_device == "cpu"` 注入；GPU 保持现有 batch size 3 行为。没有几何规则的工件因此从三次特征提取降为一次；若三路全部不同，仍执行三路；若仅两路相同，则执行两路。

### 4.2 CPU 线程配置

沿用 PaddleClas 配置中的 `Global.cpu_num_threads` 作为线程配置入口，并支持环境变量 `WORKPIECE_CPU_THREADS` 覆盖该值；环境变量优先级高于 YAML/命令行配置。当前固定基准选择的默认值为 4（部署配置和代码回退值一致）。启动时读取并校验正整数；YAML 或环境变量出现非法值时统一回退到固定默认值 4，并写入诊断日志。不在代码中无条件使用全部逻辑核心，且必须通过当前 PaddleClas/Paddle 版本实际支持的 `cpu_num_threads` 字段传递。

在线启动只做一次必要的模型预热。线程候选值的搜索在独立基准命令中完成，候选至少包括 1、2、4 和目标机器物理核心数；按固定样本的 P95 选择默认值，并同时记录 P50、P99、均值和最大值。基准环境记录逻辑/物理核心数；若运行时无法取得物理核心数，报告必须明确标注未取得并不得伪造候选结果。

### 4.3 兼容与回退

- 现有 `FastOrientationEngine`、模板缓存和 Ridge 输入接口保持不变；去重只改变 embedder 的调用集合，不改变输出张量布局。
- CPU 优化提供显式开关，关闭时可恢复原三槽位路径，用于现场对照和回滚。
- 旧缓存不含优化元数据时按旧格式加载，优化开关在运行时决定是否去重。
- 优化失败不会删除或重写工件库；错误包含方向、槽位、比较元数据和回退原因，便于定位。

## 5. 数据流

```text
输入图片
  -> 现有轻量几何处理
  -> raw/front/back 三个槽位
  -> CPU：精确等值去重（GPU：保持原 batch=3）
  -> PP-ShiTu 提取唯一槽位特征
  -> 按原槽位映射恢复特征排列
  -> 既有拼接与 Ridge 判定
  -> 原有结果对象
```

几何规则生效时不假设三路相同；去重只依据实际像素内容。因此中心反光、外部侵入、旋转和正反面差异仍由原有几何和分类逻辑处理。

## 6. 测试与验收

### 6.1 单元测试

- 三槽位完全相同：CPU embedder 调用一次，输出与未去重路径逐元素一致。
- 三槽位完全不同：调用三次（或一次 batch 中的三个唯一样本），输出顺序一致。
- 仅两槽位相同：调用两个唯一样本，映射恢复正确。
- shape/dtype 不同或比较异常：走原路径并产生诊断信息。
- GPU 配置：去重关闭，既有 batch size 3 测试继续通过。
- 线程配置：合法值生效，非法值回退且有日志。

### 6.2 集成与兼容测试

- 旧版 5+5 工件库可恢复并预测。
- 1+1、5+10、10+15 及超过 30 张模板的工件库不受影响。
- 启用/停用几何规则、正反面独立标定和不等模板数量均能预测。
- 优化开关关闭时结果与当前基线一致。

### 6.3 性能验收

使用固定 CPU、固定模型和固定样本，模型加载后预热 50 次，连续热推理至少 1000 次。快速路径每次响应显式报告全局特征预测调用次数，基准汇总实测总数和均值；旧协议若缺少该字段只能标记 unavailable，不能以槽位数冒充调用次数。进程冷启动定义为从进程启动到 `ready` 握手，当前基准执行一次启动并以 `count=1` 的统计对象报告 mean、P50、P95、P99、max；该阶段没有 `predict` 请求，因此 PP-ShiTu 调用次数和去重比例明确标记 `not_applicable`。热推理分别报告 mean、P50、P95、P99、max、PP-ShiTu 调用次数及去重比例。Qt 绘制和进程启动时间单独报告，不混入热推理算法耗时。

硬门禁是准确率/输出语义不下降、GPU 行为不变、旧库兼容；性能报告必须给出相对基线的改善幅度。若 P95 仍明显高于 25 ms，需保留实测瓶颈结论，不以未验证的模型替换或量化承诺达标。

## 7. 修改范围

预计涉及：

- `src/fast_orientation.py`：槽位去重、映射恢复和开关；
- `src/orientation_classifier.py`：CPU 开关、线程配置和预热配置；
- 必要时的配置/基准脚本：线程候选和 CPU 指标输出；
- `tests/`：去重、兼容、配置和性能回归测试。

不修改模型文件、工件库数据和 Qt 界面。

## 8. 回滚策略

将 CPU 去重和线程调优设计为独立开关；现场发现准确率、兼容性或延迟异常时关闭开关即可恢复原路径。代码分支和提交保持独立，后续可单独合并或撤回。
